Tu primer proyecto

  1. Abre Proyectos → Nuevo proyecto. Ponle un nombre, por ejemplo Solicitudes de mantenimiento, y selecciona Proceso básico.
  2. En CIM → Editar JSON, cambia el objetivo y revisa el flujo inicial. Usa Buscar para encontrar una clave y Formatear para ordenar la sangría.
  3. Dentro de datos, agrega un campo como Prioridad usando el ejemplo de abajo. Separa los objetos de una lista con comas y usa comillas dobles.
  4. Pulsa Generar aplicación. Crea un caso como Solicitante, cambia a Revisor y pulsa Completar. Comprueba el estado y el historial.

Estructura del CIM

ClaveQué debes definir
version, idUsa la versión 1 y un identificador como mantenimiento.
nombre, objetivo, entidadTítulo de la aplicación, finalidad y nombre de la entidad, por ejemplo Solicitud.
actoresQuién participa. Cada actor tiene id y nombre.
datosLos campos del caso. Cada uno declara id, nombre, tipo y, si aplica, requerido u opciones.
inicioEl actor que crea el caso, su primer estado y el nombre de la acción inicial.
estadosLas etapas con id y nombre. Marca los finales con "final": true.
transicionesAcciones con id, nombre, actor, desde y hasta. El actor y ambos estados deben existir.
oclLista de reglas. Usa [] si aún no necesitas ninguna.

Usa identificadores únicos por lista, en minúsculas, con números o guiones después de la primera letra. Cada estado debe ser alcanzable y tener un camino hacia un final. En Metamodelo base puedes consultar la estructura completa.

En CIM → Diagrama puedes editar el proceso. Abre un estado y pulsa Nueva transición desde aquí para elegir el actor y el destino. Para añadir una precondición, abre OCL y elige esa transición. Los cambios aparecen en Editar JSON.

Los botones de trabajo salen de transiciones. Para ofrecer Aprobar y Rechazar, declara dos transiciones con el mismo estado de origen y sus respectivos destinos.

Reglas OCL

El Studio implementa un subconjunto de OCL. Admite comparaciones de enteros, .size() sobre texto y and para combinar condiciones. Los tipos nuevos se validan mediante el formulario y las opciones del DSL.

context Prestamo inv CantidadValida: self.cantidad >= 1 and self.cantidad <= 5
context Prestamo::aprobar() pre MotivoSuficiente: self.motivo.size() >= 8

Una invariante se revisa al crear un caso y antes de cambiar su estado. Una precondición se comprueba al intentar la transición que indica. Sustituye Prestamo por la entidad de tu CIM y aprobar por el identificador de la acción correspondiente.

Generar, probar y exportar

  1. CIM → PIM. La primera transformación valida el proceso y produce el modelo lógico con roles, propiedades y operaciones.
  2. PIM → PSM. La segunda elige los controles web. Por ejemplo, Seleccion pasa a select. Aquí también eliges bandeja o tablero.
  3. PSM → aplicación. El generador combina el PSM con una plantilla HTML y emite los validadores ejecutables.

En PIM y PSM, abre Inspeccionar JSON para explorar las secciones de la salida generada. Usa Trazabilidad para seguir un campo desde el CIM hasta su control. Descarga el CIM para llevarlo a otro navegador, o el HTML para ejecutar la aplicación por separado. Si aparece un error, revisa el campo o la referencia indicada y vuelve a generar.

Roles de demostración y Bonita

El selector de roles de MDA Studio permite representar a varias personas durante una exposición. El HTML autónomo ejecuta el flujo en un navegador y conserva los casos localmente cuando el almacenamiento está disponible.

En Bonita, el actor se define durante el diseño y se vincula antes del despliegue a usuarios, grupos, roles o membresías de una organización. El usuario inicia sesión y accede a las tareas que puede reclamar o ejecutar. El UI Designer puede partir de un contrato de datos para crear el formulario de inicio o de una tarea.

Un destino multiusuario para MDA Studio requeriría una API con autenticación, asignación de actores a identidades, verificación de permisos y reglas en el servidor, y una base compartida con historial. El actor seguiría declarado en el CIM. La asignación a identidades se configuraría en el despliegue.

REA permitió inspeccionar los módulos instalados de identidad, contratos y diseño. Para el comportamiento de las tareas y formularios, consulta la documentación de actores de Bonita y de controles del UI Designer.
